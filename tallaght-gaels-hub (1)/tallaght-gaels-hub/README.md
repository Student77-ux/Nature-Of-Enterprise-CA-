# Tallaght Community Sports Hub

A club companion app for **Tallaght Gaels CLG**, a fictional GAA club in Tallaght,
Dublin 24. Fixtures, pitches, parking, a noticeboard, and a predicted crowd on
every fixture.

Built for TU Dublin **DATAH1010 — The Nature of Enterprise Computing**, repeat
assessment, Components 2, 3 and 4.

> **All data on this site is fictional.** The club, the opposition clubs, the
> results, the attendance figures and the noticeboard posts were generated by
> `scripts/generate_dataset.py`. No real person, club or match is described
> anywhere in this repository, and the app collects no personal data.

---

## Stack

| Layer | Choice | Why |
|---|---|---|
| Framework | Next.js 15 (App Router) | Required by the brief. Static pages where possible, one serverless function for the form. |
| Language | TypeScript, strict mode | Catches the mistakes that survive a quick eyeball. |
| Styling | One hand-written stylesheet, CSS custom properties | The accessibility settings are three attributes on `<html>`; plain CSS reacts to them in a few lines. No framework needed. |
| Charts | Hand-rolled inline SVG | No charting library. Every chart has a real `<table>` underneath it, which a chart library would not have given for free. |
| Backend | Next.js Route Handler (`/api/notices`), deployed by Netlify as a serverless function | The brief said Supabase **or** Netlify Functions. Nothing needs to be stored, so a function that validates and forgets is the smaller and more defensible choice. |
| Data | JSON seed files committed to the repo | 240 match records and 14 fixtures. Read at build time, so `/stats` is fully static. |
| Hosting | Netlify, free tier, connected to Git | Required by the brief. |

Runtime dependencies: `next`, `react`, `react-dom`. That is the whole list.

## Running it locally

```bash
git clone <your repository URL>
cd tallaght-gaels-hub
npm install
cp .env.example .env.local     # optional, see below
npm run dev                    # http://localhost:3000
```

Other scripts:

```bash
npm run build      # production build - this is what Netlify runs
npm run start      # serve the production build locally
npm run typecheck  # tsc --noEmit
```

Node 20 or newer.

## Environment variables

None are required — the app runs with all three unset. Copy `.env.example` to
`.env.local` for local development, and add the same keys in Netlify under
**Site configuration → Environment variables**.

| Variable | Required | What it does |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | No | Base URL used for page metadata. Defaults to `http://localhost:3000`. Set it to your Netlify URL in production. |
| `NEXT_PUBLIC_CLUB_EMAIL` | No | Contact address shown on the noticeboard confirmation. |
| `NOTICE_FORWARD_URL` | No | If set, noticeboard submissions are POSTed on to this URL as JSON. Left unset, submissions are validated, acknowledged and discarded. |

`NEXT_PUBLIC_` variables are readable in the browser, so nothing secret goes in
one. `NOTICE_FORWARD_URL` has no prefix and stays server-side.

## Deploying to Netlify

Full walkthrough in [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md). The short version:

1. Push this repository to GitHub.
2. Netlify → **Add new site → Import an existing project** → pick the repo.
3. Build command `npm run build`, publish directory `.next`. Both are already
   set in `netlify.toml`, so Netlify should fill them in itself.
4. Deploy. Every later push to `main` redeploys automatically.

## Features

Eight, against a minimum of four in the brief.

1. **Fixtures listing** (`/fixtures`) — every upcoming fixture, date-blocked and sorted.
2. **Search and filtering** — free-text search plus team, competition and home/away filters, with a live result count announced to screen readers.
3. **Venue directory** (`/venues`) — six locations with parking, public transport, step-free access notes, a locator diagram and a link out to OpenStreetMap.
4. **Submission form** (`/noticeboard`) — lost and found, lift shares, volunteering. Validated in the browser and again on the server.
5. **In-app reminders** (`/reminders`) — save a fixture, see a countdown. Stored in `localStorage`, never sent anywhere.
6. **Data-driven statistics** (`/stats`) — five charts built from the 240-row dataset at build time.
7. **The machine learning output** — a predicted crowd band on every fixture card and fixture page, plus a full planner at `/predict`.
8. **Accessibility settings** — larger text, high contrast, reduced motion, remembered per device.

## The attendance model

A multiple linear regression predicting how many people will attend a fixture,
so the club can plan stewards, parking and catering in advance.

- Fitted with `LINEST` on the 192 training rows in `Tallaght_Gaels_Attendance_Analysis.xlsx`.
- 10 features. Coefficients are copied into `src/lib/model.ts`, which is the only
  place the app does the arithmetic.
- **Test set: R² 0.831, RMSE 70 people, MAE 55 people, MAPE 11.4%.** That is 59%
  better than predicting the long-run average for every fixture.

The app shows a *band* (Light / Steady / Busy / Very busy) and a range rather
than a single number, because an average error of 55 people does not justify
quoting a precise one.

If you re-fit the model in the workbook, copy the new coefficients from the
`Regression` sheet (row 14 and cell B15) into `src/lib/model.ts`.

## Accessibility

The site targets WCAG 2.2 AA. Skip link, visible focus, ordered headings,
labelled fields, an error summary that takes focus, charts hidden from screen
readers with the data repeated in tables, and no meaning carried by colour
alone. See `/accessibility` on the live site for the statement, including the
problems that are still open.
